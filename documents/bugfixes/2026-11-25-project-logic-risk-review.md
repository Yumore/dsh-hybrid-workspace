# 工程逻辑风险与后续界面修复记录

审查日期：2026-11-25

初审版本：`v2.6.1`；修复版本：`v2.6.2`

范围：初审静态阅读 `lib/`、`scripts/`、`shell/`、README、设计记录和测试结构；后续按本报告实施修复并作静态复核。未运行自动化测试、真实 DSH、浏览器或 macOS 壳。

## 总体结论

这是一个 Node.js ESM 的 DeepSeek Harness（DSH）Cordis 插件。主流程围绕“单聊天会话映射到一个或多个工作区”展开：消息进入时做话题路由，生成预算化系统上下文，随后记录对话和结构化记忆；本机面板负责治理、迁移、导入导出和收件箱；收件箱任务可另建 DSH 子会话执行。

初审发现的收件箱执行目标串区、任务与工作区生命周期竞态、混合路由数据最小化、两跳记忆来源轮次、面板跨站嵌入和 macOS 壳替换风险已实施修复。修复后的静态复核还补充了取消收尾期间保持任务锁、允许收件箱记忆注入配置为 0，以及壳构建中断后恢复旧包。真实宿主接口、界面和 macOS 构建行为仍未验证。

## 主要逻辑

1. **插件入口与消息识别**：`lib/index.js` 注册 `agent/pre-step`、`session/event` 和动态系统提示词。消息进入前过滤已知插件注入内容及子代理会话，避免它们建区或污染记忆。
2. **话题路由**：先用 `lib/segment.js` 最多拆成 3 段；每段由 `lib/router.js` 基于工作区名称、范围、关键词、示例、记忆做词面评分，并使用短句粘滞、切换迟滞、两跳新话题确认等规则。混合模式遇到需要裁决的情况时可调用宿主 LLM。
3. **上下文与记忆**：路由后记录用户轮次并由 `lib/memory.js` 抽取、合并或替代记忆；`lib/lifecycle.js` 管理过期、置顶和恢复。`lib/context.js` 按工作区装配相关记忆、未决事项、最近对话和回答规则，并控制字符预算；多话题时为每个区生成独立卡片。
4. **持久化**：`lib/store.js` 把工作区、会话绑定、档案、归档和收件箱写入状态 JSON，原子替换文件；损坏状态会备份后空启动，首次使用时可从 v1 数据迁移。trace 与决策另写 JSONL。
5. **面板与治理**：`lib/ui.js` 经宿主 webServer 提供静态页面和 `/api`；API 对回环地址、Host 和 Origin 做校验。`lib/index.js` 执行修改操作，`lib/governance.js` 生成归档建议；周期扫描可自动归档空壳和长期闲置区。
6. **收件箱执行**：`lib/index.js` 按区串行、跨区限并发派发任务；`lib/executor.js` 创建独立子会话、将审批策略设为 `never`、等待完成或超时/取消，并只把结果回写任务卡。
7. **可选桌面壳**：`shell/macos/main.swift` 以 WKWebView 打开本机面板；`scripts/build-shell-macos.sh` 生成 `.app`。

## 优先处理的风险

### P1 — 收件箱任务的实际执行上下文可能与锁定工作区不一致

初审时，`lib/executor.js` 在没有绑定父会话时会回退到任意根会话，并继承它的模型、预设和 `cwd`；子会话也没有收到工作区上下文。

因此，初审版本中“手动锁定工作区”主要约束任务分组、同区串行和父会话选择；若该区没有活跃绑定会话，任务可能继承另一个项目的工作目录，涉及文件操作时可能作用于错误目录。

**修复**：只接受会话映射到所选工作区的活跃根会话，不再回退；要求其 `cwd` 是存在的绝对目录，否则明确失败。给子会话注入有上限的所选工作区上下文，不包括全局档案；任务卡显示父会话和 `cwd`。

### P1 — 有运行任务时，工作区归档、删除、合并或容量淘汰不会取消任务

初审时手动生命周期操作、迁移和容量淘汰未统一检查任务状态，可能在任务执行时移除或重映射工作区。

初审时，运行中的子会话可能在工作区被移除或合并后继续执行，最后把结果写回原工作区 ID；归档并不会自动取消它。

**修复**：归档、清空、删除、合并、迁移、治理归档和容量淘汰均检查排队/运行任务；容量没有安全淘汰对象时拒绝建区。取消会提前改持久状态、批量清空会移除任务行，因此保护条件还包含运行时执行表，直到子执行器收尾。两跳建区遇到被锁定来源时只复制暂存对话，不删除来源轮次；容量保护阻断新话题时会清除旧工作区绑定，避免继续注入旧区上下文。

### P1 — 默认混合路由会把其他工作区的内容片段交给当前模型服务

初审时 `llmJudge` 默认开启，分类请求会将跨区描述、关键词、记忆、最近对话等数据发送给当前 DSH provider/model。

设计记录 `docs/RESEARCH-v2.md` 已说明 LLM 作为兜底，但 README 主要描述为本地启发式路由，未直说默认配置可能将跨区摘要发送给模型。用户若将不同工作区用于敏感项目，会误判数据只在本地参与路由；提示词级工作区隔离不能约束 provider 接收的数据。

**修复**：`hybrid` 默认关闭 LLM；启用 `llmJudge` 后只发送当前用户消息及最多 5 个候选的 ID/名称（当前工作区纳入候选集），README 说明接收方和配置边界。显式 `mode: "llm"` 仍会走模型路由。

## 其他遗漏与中低优先级风险

### P2 — 两跳建区时，暂存助手记忆的来源轮次可能匹配不上

初审时用户记忆按宿主 turn 标记，助手记忆按工作区轮次标记，两跳建区可能无法把助手记忆与暂存用户轮次一并搬迁。

**修复**：助手记忆 `origin.turn` 优先取事件或消息中的宿主 turn，回退到该会话最近 turn；工作区轮次仍只用于排序和展示。

### P2（条件性）— 本机面板未限制跨站框架嵌入

API 对 `/api` 做了来源校验，但静态页面响应没有 `Content-Security-Policy: frame-ancestors` 或 `X-Frame-Options`。面板被有意嵌入 DSH 窗口，因此不能一概禁用 iframe；若浏览器允许外部站点嵌入回环页面，可能存在诱导点击面板操作的风险。浏览器对本机网络页面的限制会影响可利用性，本次未做浏览器实测。

**修复**：静态页面增加 `Content-Security-Policy: frame-ancestors 'self'`，允许同源 DSH iframe。此项仍未做浏览器实测。

### P2（构建操作）— macOS 壳构建脚本会递归删除目标目录并隐藏签名失败

`scripts/build-shell-macos.sh:5-9` 接受自定义输出路径后无条件 `rm -rf "$DEST"`；传错目标会删除该目录。脚本又在 `scripts/build-shell-macos.sh:33` 忽略所有 `codesign` 错误，可能在签名失败时仍打印成功路径。

**修复**：脚本要求输出路径以 `.app` 结尾，先构建并签名暂存包，成功后才替换旧包；签名错误会失败退出，替换失败或进程中断时尝试恢复旧包。未在 macOS 上执行构建。

## 已知且已有记录的边界

以下不是本次新发现，但仍会影响正确使用：

- 工作区隔离只作用于注入的提示词，原始 DSH 会话日志仍保留完整历史。
- 路由、分段、记忆提取和迁移依赖词面规则，同义改写、跨语言和隐含话题容易漏判或串区。
- `state.json` 没有跨进程锁，不应让多个 DSH 实例同时写同一个状态目录。
- `agents`、`approval` 等收件箱服务属于宿主内部接口；当前自动化测试用 fake context，不等于真实 DSH 版本兼容验证。
- 设计记录说明 LLM 路由在真实 DSH 会话中的调用比例和准确率尚未验证。

## 补充问题：窗口内浮层标题被 macOS 窗口按钮遮挡

截图显示，窗口内面板浮层左侧标题与 macOS 红黄绿窗口按钮重叠。`lib/client.js` 的全屏浮层顶部栏原本固定使用 12px 左内边距；在 macOS 标题栏覆盖网页内容的窗口布局中，这个位置落在系统按钮区域内。

**修复**：检测 macOS 平台后将顶部栏左内边距调整为 80px，为系统按钮预留空间；其他平台仍使用 12px。仅做 JavaScript 语法和差异检查，尚未在目标 DSH/macOS 窗口中进行视觉复验。

**修复**：桌面 iframe 通过宿主显式标记识别。桌面顶栏左侧显示“工作区”，右侧依次显示“浏览器打开”和“功能”，不显示“关闭”；嵌入页内重复的聊天菜单栏隐藏，“功能”通过受限的父子窗口消息打开页面抽屉。普通 Web 页面不带桌面标记，保留原顶部菜单。
