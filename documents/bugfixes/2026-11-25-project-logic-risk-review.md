# 工程逻辑风险与全工程优化盘点（2026-11-25）

审查日期：2026-11-25

初审版本：`v2.6.1`；早期修复版本：`v2.6.2`；本次盘点版本：`v2.6.3`

范围：初审静态阅读 `lib/`、`scripts/`、`shell/`、README、设计记录和测试结构；后续按本报告实施修复并作静态复核。本次再对 v2.6.3 全部生产源码、安装与构建脚本、测试入口和文档作静态盘点。未运行自动化测试、真实 DSH、浏览器或 macOS 壳。

## 总体结论

这是一个约 6.4k 行生产代码的 Node.js ESM DeepSeek Harness（DSH）Cordis 插件。主流程围绕“单聊天会话映射到一个或多个工作区”展开：消息进入时做话题路由，生成预算化系统上下文，随后记录对话和结构化记忆；本机面板负责治理、迁移、导入导出和收件箱；收件箱任务可另建 DSH 子会话执行。

初审发现的收件箱执行目标串区、任务与工作区生命周期竞态、混合路由数据最小化、两跳记忆来源轮次、面板跨站嵌入和 macOS 壳替换风险已实施修复。修复后的静态复核还补充了取消收尾期间保持任务锁、允许收件箱记忆注入配置为 0，以及壳构建中断后恢复旧包。本次盘点新增状态落盘错误未反馈、未来状态版本可能被旧代码降级覆盖、损坏文件备份失败仍覆盖等数据可靠性优先项。真实宿主接口、界面和 macOS 构建行为仍未验证。

## 主要逻辑

1. **插件入口与消息识别**：`lib/index.js` 注册 `agent/pre-step`、`session/event` 和动态系统提示词。消息进入前过滤已知插件注入内容及子代理会话，避免它们建区或污染记忆。
2. **话题路由**：先用 `lib/segment.js` 最多拆成 3 段；每段由 `lib/router.js` 基于工作区名称、范围、关键词、示例、记忆做词面评分，并使用短句粘滞、切换迟滞、两跳新话题确认等规则。混合模式遇到需要裁决的情况时可调用宿主 LLM。
3. **上下文与记忆**：路由后记录用户轮次并由 `lib/memory.js` 抽取、合并或替代记忆；`lib/lifecycle.js` 管理过期、置顶和恢复。`lib/context.js` 按工作区装配相关记忆、未决事项、最近对话和回答规则，并控制字符预算；多话题时为每个区生成独立卡片。
4. **持久化**：`lib/store.js` 把工作区、会话绑定、档案、归档和收件箱写入状态 JSON，原子替换文件；损坏状态会备份后空启动，首次使用时可从 v1 数据迁移。trace 与决策另写 JSONL。
5. **面板与治理**：`lib/ui.js` 经宿主 webServer 提供静态页面和 `/api`；API 对回环地址、Host 和 Origin 做校验。`lib/index.js` 执行修改操作，`lib/governance.js` 生成归档建议；周期扫描可自动归档空壳和长期闲置区。
6. **收件箱执行**：`lib/index.js` 按区串行、跨区限并发派发任务；`lib/executor.js` 创建独立子会话、将审批策略设为 `never`、等待完成或超时/取消，并只把结果回写任务卡。
7. **可选桌面壳**：`shell/macos/main.swift` 以 WKWebView 打开本机面板；`scripts/build-shell-macos.sh` 生成 `.app`。

## 优先处理的风险

### P1 — 收件箱任务的实际执行上下文可能与锁定工作区不一致

初审时，`lib/executor.js` 在没有绑定父会话时会回退到任意根会话，并继承它的模型、预设和 `cwd`；子会话也没有收到工作区上下文。

因此，初审版本中“手动锁定工作区”主要约束任务分组、同区串行和父会话选择；若该区没有活跃绑定会话，任务可能继承另一个项目的工作目录，涉及文件操作时可能作用于错误目录。

**修复**：只接受会话映射到所选工作区的活跃根会话，不再回退；要求其 `cwd` 是存在的绝对目录，否则明确失败。给子会话注入有上限的所选工作区上下文，不包括全局档案；任务卡显示父会话和 `cwd`。

### P1 — 有运行任务时，工作区归档、删除、合并或容量淘汰不会取消任务

初审时手动生命周期操作、迁移和容量淘汰未统一检查任务状态，可能在任务执行时移除或重映射工作区。

初审时，运行中的子会话可能在工作区被移除或合并后继续执行，最后把结果写回原工作区 ID；归档并不会自动取消它。

**修复**：归档、清空、删除、合并、迁移、治理归档和容量淘汰均检查排队/运行任务；容量没有安全淘汰对象时拒绝建区。取消会提前改持久状态、批量清空会移除任务行，因此保护条件还包含运行时执行表，直到子执行器收尾。两跳建区遇到被锁定来源时只复制暂存对话，不删除来源轮次；容量保护阻断新话题时会清除旧工作区绑定，避免继续注入旧区上下文。

### P1 — 默认混合路由会把其他工作区的内容片段交给当前模型服务

初审时 `llmJudge` 默认开启，分类请求会将跨区描述、关键词、记忆、最近对话等数据发送给当前 DSH provider/model。

设计记录 `docs/RESEARCH-v2.md` 已说明 LLM 作为兜底，但 README 主要描述为本地启发式路由，未直说默认配置可能将跨区摘要发送给模型。用户若将不同工作区用于敏感项目，会误判数据只在本地参与路由；提示词级工作区隔离不能约束 provider 接收的数据。

**修复**：`hybrid` 默认关闭 LLM；启用 `llmJudge` 后只发送当前用户消息及最多 5 个候选的 ID/名称（当前工作区纳入候选集），README 说明接收方和配置边界。显式 `mode: "llm"` 仍会走模型路由。

## 其他遗漏与中低优先级风险

### P2 — 两跳建区时，暂存助手记忆的来源轮次可能匹配不上

初审时用户记忆按宿主 turn 标记，助手记忆按工作区轮次标记，两跳建区可能无法把助手记忆与暂存用户轮次一并搬迁。

**修复**：助手记忆 `origin.turn` 优先取事件或消息中的宿主 turn，回退到该会话最近 turn；工作区轮次仍只用于排序和展示。

### P2（条件性）— 本机面板未限制跨站框架嵌入

API 对 `/api` 做了来源校验，但静态页面响应没有 `Content-Security-Policy: frame-ancestors` 或 `X-Frame-Options`。面板被有意嵌入 DSH 窗口，因此不能一概禁用 iframe；若浏览器允许外部站点嵌入回环页面，可能存在诱导点击面板操作的风险。浏览器对本机网络页面的限制会影响可利用性，本次未做浏览器实测。

**修复**：静态页面增加 `Content-Security-Policy: frame-ancestors 'self'`，允许同源 DSH iframe。此项仍未做浏览器实测。

### P2（构建操作）— macOS 壳构建脚本会递归删除目标目录并隐藏签名失败

`scripts/build-shell-macos.sh:5-9` 接受自定义输出路径后无条件 `rm -rf "$DEST"`；传错目标会删除该目录。脚本又在 `scripts/build-shell-macos.sh:33` 忽略所有 `codesign` 错误，可能在签名失败时仍打印成功路径。

**修复**：脚本要求输出路径以 `.app` 结尾，先构建并签名暂存包，成功后才替换旧包；签名错误会失败退出，替换失败或进程中断时尝试恢复旧包。未在 macOS 上执行构建。

## 已知且已有记录的边界

以下不是本次新发现，但仍会影响正确使用：

- 工作区隔离只作用于注入的提示词，原始 DSH 会话日志仍保留完整历史。
- 路由、分段、记忆提取和迁移依赖词面规则，同义改写、跨语言和隐含话题容易漏判或串区。
- `state.json` 没有跨进程锁，不应让多个 DSH 实例同时写同一个状态目录。
- `agents`、`approval` 等收件箱服务属于宿主内部接口；当前自动化测试用 fake context，不等于真实 DSH 版本兼容验证。
- 设计记录说明 LLM 路由在真实 DSH 会话中的调用比例和准确率尚未验证。

## 2026-11-25 全工程优化清单

以下项目来自对当前 `v2.6.3` 源码、脚本、测试入口与文档的静态盘点。优先级表示建议顺序；“条件性”项目只有在对应部署/错误条件出现时才会触发。该盘点未运行测试或真实宿主。

### P1：先修复数据可靠性与验证门禁

1. **落盘失败仍返回操作成功。** `lib/index.js:245-270` 的 `saveNow()` 捕获写盘错误后只记日志，`flush()` 仍正常完成；管理 API 随后仍可返回成功。磁盘满、权限错误或短暂 I/O 故障时，用户可能看到“已保存”，重启后却丢失变更。让失败从 `flush()` 传回 API/界面，保留 dirty 状态并加有限重试与明确的保存错误提示；补写盘失败测试。
2. **损坏状态备份失败后继续覆盖原文件。** `lib/store.js:229-237` 忽略 `copyFile()` 错误后仍保存空状态。应先确保原文件成功保全，否则停止初始化并保留原始文件；扩展 `test/state-corrupt.test.mjs` 覆盖备份失败及恢复提示。
3. **状态 schema 版本没有校验。** `lib/store.js:221-227` 只看 `workspaces` 字段，`normalizeState()` 又固定写回版本 2。将来旧版插件打开更高版本状态时，可能丢弃新字段并覆盖新格式。应在推出下一个 schema 版本前加上未知高版本拒绝写回、明确提示的保护；每个已支持 schema 版本走显式迁移。
4. **当前测试版本断言已经漂移。** 包与 UI 是 `2.6.3`，但 `test/load-check.mjs:20`、`test/ui-smoke.mjs:38`、`test/v23.test.mjs:191` 仍要求 `2.6.1`。按静态检查，这些断言与现有源码不一致，`npm test` 会在相应项失败；未实际运行测试。让 UI 从单一版本源取值，测试动态读取 package 版本，避免后续发版继续漂移。
5. **同一状态目录不能安全地由多个 DSH 进程同时写入（条件性，README 已记录）。** 当前 `lib/index.js` 的写入队列只约束一个插件实例，`lib/store.js` 原子替换也没有跨进程锁。多实例会出现最后写入覆盖较早状态。若部署需要并行实例，应增加目录级单写者锁/租约，或启动时检测并拒绝第二个 writer；增加双实例竞争测试。若始终保证单实例，则把这条部署前提保留在醒目配置说明中。

### P2：控制长期运行成本与运维风险

6. **决策和 trace 日志无磁盘上限。** `lib/store.js:204-213` 追加 JSONL 不轮转，启动读取时先将整个文件读入内存再截取末尾；`lib/index.js:201,346` 又在每次日志写入时丢弃 Promise，外层同步 `try/catch` 捕获不到异步写失败。设置大小/时间保留上限、按字节读取尾部、串行写入并处理 `.catch()`；提供清理策略，减少用户消息片段长期留存。
7. **面板轮询反复传输完整归档快照。** `lib/index.js:1162-1168` 将全部归档连 turns/memories 返回；`lib/ui.js:1218-1222` 每 30 秒轮询，而归档卡片只展示元数据。改为归档摘要列表，用户展开或恢复时再加载单条详情；同时阻止轮询重叠及旧响应覆盖新状态，并按变更局部更新 DOM。
8. **安装/卸载不是事务。** `scripts/install.mjs:94-126` 忽略备份失败，先改软链，再顺序写 `package.json` 和 `cordis.patch.yml`。中途出错会留下半安装/半卸载。先写临时文件并校验，成功后原子替换；任何备份或替换失败时回滚软链与配置，增加 dry-run/失败注入测试。
9. **独立壳 URL scheme 校验在 JS/Swift 两侧不一致。** `lib/shell-os.js:5-11` 只看 loopback 主机和路径，因此导出的校验函数会接受其它 scheme；但 `shell/macos/main.swift:8-13` 仅从参数中选择 `http://` / `https://`，实际会忽略其它 scheme 并退出。统一限制为部署支持的 `http:`/`https:`（当前本机面板主要是 HTTP），在 JS 侧提前拒绝，并补 `file:`、`data:` 等测试，避免错误启动与两套规则漂移。
10. **本地状态文件权限依赖进程 umask。** `lib/store.js:197-206` 创建目录和状态/日志文件时未指定权限，而数据包含聊天片段、记忆和任务内容。共享设备或自定义宽权限目录可能扩大本地读取范围。新目录使用 `0700`、数据/临时文件 `0600`，并对既有文件提供审慎迁移；先在真实用户目录验证权限策略。
11. **LLM 路由等待时间依赖宿主取消信号。** `classify()` 将 `payload.signal` 传给 provider，但插件没有独立墙钟超时；多话题逐段 await 时最多串行触发多次判断。增加超时后转回词面路由的明确回退；对多段请求考虑一次批量判断，并记录延迟/失败比例。
12. **宿主兼容边界缺少自动验证。** `package.json:38-40` 声明 Cordis `>=4.0.2 <5.0.0`，真实 DSH 的 `agents`、`approval`、`webServer` 和事件形状却只通过 fake context 间接覆盖；当前已跟踪文件也未见 CI 工作流。建立 CI 执行 `npm test`，并对声明支持的最低/最高宿主版本跑接口合同和收件箱取消/超时集成验证；明确支持的 Node 版本。

### P3：降低结构复杂度并提高路由评估可信度

13. **入口与 UI 文件职责过于集中。** `lib/index.js` 约 1.7k 行，包含路由、会话钩子、状态/生命周期、收件箱、导入导出和所有管理操作；`applyOp()` 是大量分支的命令分发。`lib/ui.js` 约 1.3k 行，同时嵌入 CSS/HTML/浏览器脚本并实现 HTTP API。保留现有 router/memory/executor 等领域模块，将 workspace 命令、收件箱命令、持久化接口和面板 HTTP 层逐步抽出；每次提取保持 API 行为不变并用现有 fake-context 测试。
14. **路由评估仍以合成题为主。** `test/eval-synth.mjs` 已有 100+ 合成问题和 purity/cohesion 阈值，这是良好基础；但真实用户短句、跨语言、纠错后回归、同名项目和多话题边界仍需人工审阅样本。增加经过脱敏/授权的固定评估集与误切/漏切指标，不将真实用户文本未经许可写入 fixture。
