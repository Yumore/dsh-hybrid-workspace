# 工程逻辑与风险审查

审查日期：2026-11-25

审查版本：`v2.6.1`（当前 `main` / `origin/main`）

范围：静态阅读 `lib/`、`scripts/`、`shell/`、README、设计记录和测试结构；未修改应用代码。

## 总体结论

这是一个 Node.js ESM 的 DeepSeek Harness（DSH）Cordis 插件。主流程围绕“单聊天会话映射到一个或多个工作区”展开：消息进入时做话题路由，生成预算化系统上下文，随后记录对话和结构化记忆；本机面板负责治理、迁移、导入导出和收件箱；收件箱任务可另建 DSH 子会话执行。

路由、记忆、迁移和本机 API 都有较多边界处理和回归测试。当前更值得优先处理的是收件箱执行的工作区/工作目录绑定，以及运行任务期间工作区被归档或删除的竞态；此外，默认混合路由会把多工作区摘要发给当前模型服务，这一数据边界在 README 中不够明确。

## 主要逻辑

1. **插件入口与消息识别**：`lib/index.js` 注册 `agent/pre-step`、`session/event` 和动态系统提示词。消息进入前过滤已知插件注入内容及子代理会话，避免它们建区或污染记忆。
2. **话题路由**：先用 `lib/segment.js` 最多拆成 3 段；每段由 `lib/router.js` 基于工作区名称、范围、关键词、示例、记忆做词面评分，并使用短句粘滞、切换迟滞、两跳新话题确认等规则。混合模式遇到需要裁决的情况时可调用宿主 LLM。
3. **上下文与记忆**：路由后记录用户轮次并由 `lib/memory.js` 抽取、合并或替代记忆；`lib/lifecycle.js` 管理过期、置顶和恢复。`lib/context.js` 按工作区装配相关记忆、未决事项、最近对话和回答规则，并控制字符预算；多话题时为每个区生成独立卡片。
4. **持久化**：`lib/store.js` 把工作区、会话绑定、档案、归档和收件箱写入状态 JSON，原子替换文件；损坏状态会备份后空启动，首次使用时可从 v1 数据迁移。trace 与决策另写 JSONL。
5. **面板与治理**：`lib/ui.js` 经宿主 webServer 提供静态页面和 `/api`；API 对回环地址、Host 和 Origin 做校验。`lib/index.js` 执行修改操作，`lib/governance.js` 生成归档建议；周期扫描可自动归档空壳和长期闲置区。
6. **收件箱执行**：`lib/index.js` 按区串行、跨区限并发派发任务；`lib/executor.js` 创建独立子会话、将审批策略设为 `never`、等待完成或超时/取消，并只把结果回写任务卡。
7. **可选桌面壳**：`shell/macos/main.swift` 以 WKWebView 打开本机面板；`scripts/build-shell-macos.sh` 生成 `.app`。

## 优先处理的风险

### P1 — 收件箱任务的实际执行上下文可能与锁定工作区不一致

`lib/executor.js:56-78` 会先寻找绑定到所选工作区的父会话；找不到时退回最近的任意绑定会话或任意根会话。随后 `lib/executor.js:194-212` 继承该父会话的模型、预设和 `cwd`。新子会话从空事件历史开始（`inheritedEventCount: 0`），`lib/executor.js:256-260` 只注入通用说明、工作区名称和任务文本；它没有收到工作区范围、关键词、摘要或记忆。默认情况下 `lib/index.js:1548-1550` 又会跳过子代理路由与上下文注入。

因此，UI 上“手动锁定工作区”目前主要约束任务分组、同区串行和父会话选择；如果该区没有活跃绑定会话，任务可能继承另一个项目的工作目录，且无该区上下文。涉及代码修改或文件操作时，可能作用于错误目录。

**建议**：把工作区与明确的执行目标（父会话或项目目录）绑定；没有匹配目标时停止执行并提示用户选择，不要静默回退到任意会话。若任务确实需要工作区知识，再显式提供经裁剪的只读范围/摘要，并在 UI 展示最终父会话和 `cwd`。

### P1 — 有运行任务时，工作区归档、删除、合并或容量淘汰不会取消任务

自动扫描和 `governanceApply` 会检查 `inboxRuns` 并跳过有任务运行的区（`lib/index.js:318`、`1384-1386`），但手动 `archive`、`delete`、`merge` 路径（`1495-1529`）没有同样的保护；容量达到上限时，`createWorkspace` 也会直接归档最旧区（`347-357`）。任务执行器只在任务取消或超时时收到 abort；工作区操作本身不取消它。

运行中的子会话可能在工作区已被移除或合并后继续执行，操作可能产生副作用，最后任务卡仍将结果写回原工作区 ID。归档不等于取消，也没有向用户提示该任务仍在运行。

**建议**：所有会移除或重映射工作区的入口统一检查活动任务；要求用户先取消/等待，或由系统先 abort 并等待执行器收尾后再提交变更。容量淘汰也应跳过活动任务工作区，并在无可淘汰对象时明确拒绝新建。

### P1 — 默认混合路由会把其他工作区的内容片段交给当前模型服务

`lib/index.js:25` 默认 `llmJudge: true`，`mode: hybrid` 遇到 `ask-llm` 才调用分类器。分类请求（`lib/index.js:462-510`）包含最多 20 个工作区的名称、范围、关键词、代表问法和数组尾部至多 2 条 active decision 记忆，以及当前区最近 4 轮和本条用户消息。这些数据会发给当前 DSH provider/model。

设计记录 `docs/RESEARCH-v2.md` 已说明 LLM 作为兜底，但 README 主要描述为本地启发式路由，未直说默认配置可能将跨区摘要发送给模型。用户若将不同工作区用于敏感项目，会误判数据只在本地参与路由；提示词级工作区隔离不能约束 provider 接收的数据。

**建议**：在 README 和面板配置中明确披露触发条件、发送字段和数据接收方；提供清晰的本地词面模式（例如 `llmJudge: false` / `mode: lexical`）作为隐私选项，并考虑只向模型发送候选 ID 与最小化的身份字段。

## 其他遗漏与中低优先级风险

### P2 — 两跳建区时，暂存助手记忆的来源轮次可能匹配不上

用户消息的记忆来源使用宿主 `payload.turn`（`lib/index.js:688`）；助手记忆的 `origin.turn` 使用工作区轮次 `target.rounds`（`858-860`）；第二跳搬移时却用 `pending.originTurn` 与记忆 `origin.turn` 比较（`619-628`）。宿主轮次和工作区轮次在迁移、已有会话或会话编号不一致时可能不同，导致助手结论留在旧区，即使对应 user/assistant 对话轮已搬到新区。

**建议**：统一来源主键，至少使用同一 `sessionId + host turn + role` 方案标记该轮用户与助手记忆；增加宿主轮次与工作区轮次不同的回归场景。

### P2（条件性）— 本机面板未限制跨站框架嵌入

API 对 `/api` 做了来源校验，但静态页面响应没有 `Content-Security-Policy: frame-ancestors` 或 `X-Frame-Options`。面板被有意嵌入 DSH 窗口，因此不能一概禁用 iframe；若浏览器允许外部站点嵌入回环页面，可能存在诱导点击面板操作的风险。浏览器对本机网络页面的限制会影响可利用性，本次未做浏览器实测。

**建议**：通过 `frame-ancestors 'self'` 限制为同源嵌入，并验证 DSH 自定义协议转发和原生壳仍可使用；不要把此项视为已复现漏洞。

### P2（构建操作）— macOS 壳构建脚本会递归删除目标目录并隐藏签名失败

`scripts/build-shell-macos.sh:5-9` 接受自定义输出路径后无条件 `rm -rf "$DEST"`；传错目标会删除该目录。脚本又在 `scripts/build-shell-macos.sh:33` 忽略所有 `codesign` 错误，可能在签名失败时仍打印成功路径。

**建议**：校验目标路径位于预期应用输出目录，或要求目标是名为 `.app` 的目录；对签名失败明确输出状态，并区分“生成成功”和“签名成功”。

## 已知且已有记录的边界

以下不是本次新发现，但仍会影响正确使用：

- 工作区隔离只作用于注入的提示词，原始 DSH 会话日志仍保留完整历史。
- 路由、分段、记忆提取和迁移依赖词面规则，同义改写、跨语言和隐含话题容易漏判或串区。
- `state.json` 没有跨进程锁，不应让多个 DSH 实例同时写同一个状态目录。
- `agents`、`approval` 等收件箱服务属于宿主内部接口；当前自动化测试用 fake context，不等于真实 DSH 版本兼容验证。
- 设计记录说明 LLM 路由在真实 DSH 会话中的调用比例和准确率尚未验证。

## 审查范围与验证说明

本次是静态源码与文档审查；未运行 `node test/all.mjs`，未启动真实 DSH、浏览器或 macOS 壳，也未验证真实 provider 的路由数据流。以上高优先级发现由代码路径直接支持；两跳记忆和跨站框架风险分别是条件性边界，需要对应集成/浏览器场景再确认。
