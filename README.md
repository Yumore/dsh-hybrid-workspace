# dsh-hybrid-workspace v2.3.1

一个 DeepSeek Harness 插件：仍然只有一个聊天框，但每句话（或一条消息里的多个话题）会先被判断属于哪个「工作区」，回答只装配相关区的工作范围、结构化记忆和最近几轮对话。

v2.3 在 v2.2 的上下文迁移之上补齐了日常运维需要的几块：每区策略（上下文上限、注入记忆数、是否允许自动切走）、工作区导出/导入（JSON 与 Markdown）、路由 trace 解释（命中哪些词、为什么切区）、迁移预览逐条勾选（可按轮次排除，也可补选低分候选）、可选的 cost-meter 会话费用桥接，以及 supersede 结论演变时间线。仍然不调用 LLM 做分类。v2.3.1 修复评审发现的边界问题，并补上连续问句拆段；v2 是对早期 v1 的重构，代码独立成包。

## 为什么开发它

这个插件最初是为了解决我自己的问题：我在同一个聊天框里同时处理 imPOS 收银终端的线上运维、华润餐饮项目、DSH 插件开发和零碎事务。用得越久，三个矛盾越明显：

- **历史互相污染**：一个聊天框里混着运维、业务系统、日常杂事，历史越长越互相干扰，A 项目的细节容易被带进 B 项目。
- **全量上下文又贵又稀释注意力**：全部历史都塞进上下文，既费 token 又让模型抓不住重点；粗暴截断又会丢结论。
- **手工多会话切换成本高**：开很多会话/窗口当然能隔离，但每天来回切换、同步结论很累，也不适合“随口问一句”的场景。

所以 v2 的目标不是“再做一个聊天客户端”，而是给单聊天框加一层本地、可解释的工作区路由：消息先判断属于哪个工作区，回答只装配相关区的工作范围、结构化记忆和最近几轮对话。它不追求“全自动理解一切”，而是让常见的项目切换稳定、可预期，并在拆错/路由错时能在面板里改回来。

设计上刻意做了几个取舍：

- **确定性优先**：默认词面 + IDF + 迟滞，只有模糊时才问 LLM；不把每次路由都变成一次模型调用。
- **本地优先**：状态、记忆、归档都在 `$DSH_HOME` 下，可备份、可导出、可审计。
- **可解释**：每条 trace 记录问句词、命中词、分数、分差和分支原因，不只看一个黑盒分数。
- **可迁移**：导出 JSON/Markdown，导入重编 id，不锁死在某台机器。
- **不物理切会话**：保留单聊天框体验；隔离是提示词级，原始会话日志仍在 DSH 自己那里。

v2 的做法不是「物理切分会话」，而是**路由 + 结构化记忆 + 预算化装配**：

```text
用户消息
  → 过滤插件注入消息（不记账、不建区）
  → 多话题拆段（空行/编号/连接词/连续问句，最多 3 段；当前区锁定自动切走时整条不拆）
  → 每段路由（字段加权 IDF + 迟滞；模糊时才问 LLM）
  → 每段绑定/新建工作区
  → 抽取记忆（决策/事实/待办/问题），合并、supersede
  → 规则分类生命周期（profile / durable / episodic / scratch）+ 本地 TTL；全局档案单独存
  → 单话题注入当前区一张卡（按区策略或全局预算，默认 ≤2400 字符）；多话题注入多区卡
  → 需要时手动新建目标区，按关键词迁移对话/记忆；预览可逐条勾选/补选；搬空的来源归档并重绑会话
  → 模型回答；回答按编号分发到本次涉及的区
```

## 功能一览

- **单框多工作区**：每个工作区有自己的范围、关键词、摘要、对话和记忆；消息按字段加权 IDF + 迟滞路由，短句粘住、强信号切换、连续两条才切，减少来回跳。
- **多话题拆段**：一条消息里的空行、行首/行内编号、少量连接词、连续问句可以拆成最多 3 段，分别路由和记忆；助手回答能解析出编号时按段分发。
- **结构化记忆**：把对话抽成决策/事实/待办/问题，支持 ADD / NOOP / supersede；旧结论保留但标记为被替代，面板里按链展示“旧结论 → 新结论”。
- **预算化上下文**：单话题只注入当前区一张卡（默认 ≤2400 字符），多话题注入多区卡；按相关记忆、未决事项、最近对话、全局档案的优先级裁剪，每区还能单独设上限、注入条数和是否允许自动切走。
- **可解释路由**：trace 记录问句词、命中词、候选分数、首选/当前分差和分支原因（如 `sticky-short`、`switch-pending`、`multi-new`），不是只给一个分数。
- **上下文迁移**：先聊后建区；按关键词预览，按轮次勾选/取消，低分候选可手动补选；搬空来源归档并重绑会话，部分迁移保留剩余内容。
- **面板**：工作区卡、记忆明细、生命周期/剩余期限、结论演变、上下文构成、路由 trace、归档恢复、每区策略、导出/导入，都在 `/hybrid-workspace/` 一个页面里。
- **导出 / 导入**：JSON 与 Markdown 双格式，默认包含全局档案；导入重编工作区/记忆 id，不覆盖现有数据。
- **可选费用桥接**：检测到 `dsh-cost-meter` 时显示最近 12 个会话的合计费用、token 和调用次数；没装则整块隐藏，不产生依赖。
- **数据安全**：过滤 `[Plugin context from ...]` 等插件注入消息，不建区、不记账；v2 状态损坏时备份后从空状态启动，不回退覆盖 v1；面板 POST 校验同源与 JSON Content-Type。

## 最好和哪些插件一起用

运行环境：DeepSeek Harness 0.2.x / cordis ≥4.0.2。本插件不依赖其他插件也能工作；下面这些是“装了更顺”或“最好别同时开”的经验。

| 插件 | 建议 | 说明 |
| --- | --- | --- |
| `dshmarket` | 推荐 | 在 DSH 内浏览、安装、更新本插件。它负责插件管理，不参与上下文路由。 |
| `dsh-cost-meter` | 可选，推荐 | 装了并暴露 `costMeter` 服务时，面板显示最近 12 个会话的合计费用/token/调用次数；没装则整块隐藏。 |
| `billion-context` | 可共存 | 它做长上下文压缩，本插件做路由和按区装配；同时开启时注意两者预算叠加，先看面板的字符统计，别让压缩后的内容又被重复裁一遍。 |
| `dsh-ops` | 可共存 | 终端/运维工具，和本插件职责不冲突；运维消息仍会按工作区路由，插件注入的步骤消息会被过滤。 |
| `dsh-auto-memory` | 可共存，建议分工 | 它是跨 App 的文件型记忆真源，本插件是工作区内的结构化记忆；两套都从对话抽取时可能重复，建议明确哪套负责长期偏好、哪套负责项目结论，并观察面板是否重复注入。 |
| 其他上下文构成/压缩插件（如 `dsh-context`） | 不需要 | 上下文构成面板、压缩和本插件的预算装配有重叠；本机已移除 `dsh-context`，避免同一份上下文被两套逻辑重复处理。 |

## 与 v1 的差异

| 维度 | v1 | v2 |
| --- | --- | --- |
| 路由 | 词面覆盖率，一有命中就换区 | 字段加权 IDF + 迟滞（连续两条才切、短句粘住、强信号直切） |
| 多话题 | 一条消息只归一个区 | 按空行/编号/连接词/连续问句拆段，最多 3 个区，分别路由与记忆 |
| 记忆 | 每轮抽 1~3 条「结论账本」平铺 | 分类型记忆 + ADD/NOOP/supersede + 相关度检索 + MMR 去重 + 生命周期分层/TTL |
| 注入 | 最近 10 条账本，与当前问题无关也塞 | 只装与当前问题相关的 top 记忆 + 未决事项 + 最近 4 轮 |
| 预算 | 约 700 token 封顶 | 默认 2400 字符，硬预算，按优先级裁剪 |
| 面板 | 卡片 + 归档 | 增加记忆类型统计、记忆明细、代表性问法、路由判定 trace、合并 |
| 上下文迁移 | 只能整区合并 | 手动新建目标区，按关键词挑部分对话/记忆迁移；预览可逐条排除/补选；默认归档搬空的来源并重绑会话 |
| 每区策略 | 无 | 每区可配上下文上限、注入记忆数、是否允许自动切走；锁定后不再自动换区 |
| 可移植性 | 状态文件不可读 | 面板导出/导入 JSON 或 Markdown；导入重编 id，不覆盖现有区 |
| 路由可解释 | 只有分数 | trace 显示问句词、命中词、候选分数、为什么留下/切换 |
| 结论演变 | 只有 superseded | 旧结论划线 → 新结论，按链展示时间线 |
| 费用 | 需要另装插件 | 检测到 cost-meter 时显示最近 12 个会话合计费用，没有则完全隐藏 |
| 状态 | v1 schema | v2 schema，首次启动只读迁移 v1 |

## 配置

在 profile 的 `cordis.patch.yml` 对应条目下配置；未写的项用默认值。

```yaml
- id: hybrid-workspace
  name: dsh-hybrid-workspace-v2
  config:
    mode: hybrid            # hybrid | lexical | llm
    autoCreate: true
    routeAccept: 0.48       # 接受某个已有工作区的分数线
    sameTopicAccept: 0.3    # 留在当前区所需的最低分
    switchMargin: 0.14      # 候选领先当前区多少才考虑切换
    pendingSwitch: 2        # 连续几条同候选才真正切换
    shortSticky: 12         # 短于该字数的消息粘在当前区
    unseenPenalty: 0.15     # 从未出现过的词按多少 IDF 计权
    contextMaxChars: 2400   # 单话题注入块字符预算
    multiTopic: true         # 一条消息里的多个话题分别路由
    multiTopicMax: 3         # 最多拆成几个工作区
    segmentMinChars: 12      # 短于此的片段并入相邻段
    multiContextMaxChars: 3000 # 多话题注入总预算
    memoryInject: 8         # 最多注入几条相关记忆
    recentTurns: 4          # 注入最近几轮对话
    memoryKeep: 300         # 每个工作区最多保留多少条记忆
    profileKeep: 50         # 全局档案上限（跨工作区，独立存放）
    profileInject: 4        # 每次最多注入几条全局档案
    sweepIntervalMs: 60000  # 懒清扫节流：多久检查一次过期；0 = 每次
    maxWorkspaces: 60
    archiveKeep: 20
    panelPath: /hybrid-workspace
    debug: true
```

## 面板

插件挂载在宿主 webServer 上（默认 `/hybrid-workspace/`），自包含 HTML + JSON API，无外部资源、无前端构建：

- 顶部统计：工作区数、活跃记忆、全局档案、已过期、活跃会话、上下文合计（字符 / 估算 token / 每区上限）、多话题轮数、LLM 判定次数、归档数；检测到 cost-meter 时额外显示最近 12 个会话合计费用。
- 顶部「导出」「导入」：导出可勾选部分工作区或全部，格式选 JSON 或 Markdown；导入接受本插件导出的 JSON/Markdown，单个文件最多 8MB，导入会重编工作区与记忆 id，不影响现有区。
- 「上下文构成 · 所有工作区」：按工作区卡 / 全局档案 / 相关记忆 / 未决事项 / 最近对话 / 回答规则拆出字符占比，便于判断预算被谁吃掉。
- 「全局档案」：跨工作区注入的长期偏好/身份/约定，显示层级、剩余期限、置顶/取消置顶；profile 默认永久，取消置顶也不会立刻过期。
- 工作区卡片：标题「话题：xxx」，下方显示该区下一轮注入的占用（字符、估算 token、预算百分比与进度条）与策略（上下文上限 / 注入记忆数 / 自动切走）；再往下是轮数、命中、会话数、范围、关键词、记忆类型统计、记忆明细（层级、剩余期限、置顶/恢复按钮、superseded 划线）、结论演变时间线、代表性问法、最近对话。
- 卡片右上角「归档」「删除」：归档是软删除，保留快照并解绑会话，可在「已归档」恢复；删除是硬删除，移除该区及其注入上下文、解绑会话并清空最后查询，不可恢复。
- 顶部「新建工作区」：先建一个空目标区，填名称与范围，再迁移内容进去。
- 顶部「迁移选中」：在卡片右上角勾选一个或多个来源区，按关键词预览并迁移；留空关键词表示全部迁移。
- 底部操作：重命名、改范围、合并到另一个区、清空记忆与最近对话。
- 记忆生命周期：profile（全局档案，永久）/ durable（长期，默认 180 天）/ episodic（过程，14 天）/ scratch（临时，12 小时）；todo/question 为 30 天。过期只标记 expired，不硬删，面板可恢复；置顶会覆盖 TTL。
- 「最近路由判定」：每条消息选了哪个区、分数、是否调用了 LLM；一条消息拆成多段时显示 1/3 这类段号。展开某条 trace 可看到问句词、命中词、首选分、当前区分、分差、每个候选的命中词，以及「为什么」用中文说明 how 分支（如 sticky-short、switch-pending、locked）。
- 「已归档」：手动归档或满额淘汰的快照，显示归档时间、原因、原占用，可恢复或彻底删除；上下文迁移搬空的来源只留元数据，显示「已迁移到 XXX」且不提供恢复，避免原文重复注入。

## 上下文迁移

先聊后建区：开始时几句话混在几个区里，后来某个话题值得单独维护，可以手动新建一个工作区，再把相关内容搬过去。入口在面板顶部「新建工作区」和「迁移选中」。

流程：

1. 勾选一个或多个来源区。
2. 点「迁移选中」，输入目标区 id/名称；留空会先新建目标区。
3. 输入关键词（留空 = 全部迁移）。预览会列出每个来源命中/剩余多少条、目标区，并按轮次列出每条对话/记忆，可逐条取消勾选。
4. 预览下方还有「低分候选 · 默认不搬」：这些条目分数低于阈值但接近，勾选后会作为 `include` 补进目标区，适合词面匹配漏掉的步骤/回答。
5. 确认后真正搬迁；被搬空（或选了 `always`）的来源归档，当前会话自动重绑到目标区。

匹配规则：对来源的对话、记忆、代表性问法建 IDF，按关键词覆盖率评分；命中某轮任一条对话时，同轮助手回答一起搬（`roundContext`，默认开）。只做词面匹配，不做同义改写；未命中的内容留在来源区。低分候选不会自动搬，必须在预览里勾选。

归档规则：`archiveMode=auto`（默认）只有来源被搬空才归档；`always` 总是归档来源；`never` 保留空来源。来源还有剩余内容时，归档快照仍可恢复；被搬空的来源只存元数据（`restorable:false`），不能恢复，避免原文重复注入。迁移只动工作区，不动全局档案。

API 形态（面板同一入口）：

```json
{"op":"migrate","sourceIds":["ws_a"],"into":"ws_b","query":"断线","mode":"match","dryRun":true}
```

`dryRun` 默认 true；确认时传 `dryRun:false`。`mode:"all"` 表示全部迁移；`rebindSessions:false` 可关闭会话重绑。预览返回的每个条目都有 `key`；`exclude` 传取消勾选的 key，`include` 传勾选的低分候选 key。

## 每区策略

卡片上的「策略」按钮可改三个值，留空表示继承全局：

- `contextMaxChars`：该区单次注入字符上限（600–12000），受全局 `contextMaxChars` 再封顶。
- `memoryInject`：该区最多注入几条记忆（0–20），受全局 `memoryInject` 再封顶。
- `autoSwitch`：是否允许路由器把消息自动切到别的区；设为 false 后当前区锁定，短句和多话题拆分也不会把它带走，直到在面板改回来。

## 导出 / 导入

- 导出 JSON：`{format:"dsh-hybrid-workspace",version:1,exportedAt,workspaces:[...],profile:[...]}`，默认包含工作区字段、对话、记忆和全局档案；传 `withProfile:false` 可只导出工作区。
- 导出 Markdown：每个工作区一个 `# 工作区：` 文档，记忆/对话按 `###` 块；有全局档案时额外输出 `# 全局档案` 文档，人可读，也可被本插件重新导入。
- 导入：接受本插件导出的 JSON/Markdown（也接受单个工作区对象），单文件最多 8MB；导入不按 5 个工作区截断。工作区与记忆 id 全部重编，`supersedes/supersededBy` 在导入副本内重新指向，不会覆盖已有区。全局档案单独解析、按规范化文本去重合并；导出时每个工作区最多保留 500 轮对话 / 500 条记忆。

## 可选的 cost-meter 桥接

如果宿主装了 `dsh-cost-meter` 并暴露 `costMeter` 服务，插件通过 `ctx.inject(['costMeter'])` 读取会话费用、token 与调用次数，面板汇总最近 12 个会话显示在统计行；没有该服务时整块隐藏，不产生依赖。显示的是跨会话合计，不做按工作区/按会话分摊。

## 状态与日志

默认在 `$DSH_HOME/hybrid-workspace-v2/`：

- state.json：工作区、工作区记忆、全局档案（profile）、会话绑定、归档；原子写，300ms 防抖。迁移归档额外保留 `restorable`、`migratedTo`、`movedTurns`、`movedMemories`。
- `decisions.log`：新建/路由/合并/清空等决策。
- `trace.jsonl`：最近路由判定（候选分数、how 字段）。

v1 的 `$DSH_HOME/hybrid-workspace/state.json` 只在 v2 状态不存在时读取一次用于迁移，**不会修改 v1 文件**。

## 安装

在源码目录执行：

```bash
node scripts/install.mjs                     # dry-run，先看要改什么
node scripts/install.mjs --apply             # 写入 profile
node scripts/install.mjs --apply --replace   # 已装 v1 时：先卸 v1 再装 v2
```

脚本会改四处并备份：profile 的 `package.json`（file: 依赖）、`dsh.profile.bundles`、`cordis.patch.yml`、`node_modules` 软链。装完需要重启 DeepSeek Harness。

`--replace` 会移除 v1 的依赖、bundle、补丁块和软链，但**不会恢复 v1**；v1 的 state.json 仍保留，v2 首次启动会只读迁移。

## 已知边界

- **隔离是提示词级**：会话的原始历史仍在 DSH 会话日志里；v2 只是不把其他区的内容注入当前步骤。真正的物理隔离（一区一会话/子代理）尚未启用，见 `docs/plan-b.md`。
- **记忆抽取是启发式的**：无实体、无线索词的纯叙述句会漏；抽取器是规则，不是模型。
- **路由是词面 + IDF**：同义改写、跨语言、极短指代依赖迟滞或 LLM 兜底；LLM 判定默认只在模糊时调用。
- **单进程状态**：`state.json` 无跨进程锁；同一 `$DSH_HOME` 多实例并发写有风险。
- **面板无鉴权**：依赖宿主 webServer 绑定回环地址；不要暴露到公网。
- **生命周期是规则分类**：profile/scratch/episodic 靠关键词与角色判断，可能把「记住」类业务句误升为全局；面板可取消置顶，或后续再改规则。
- **过期是软删除**：只把状态标为 expired，记录仍保留在 state.json，面板可恢复；不会自动物理清理。
- **全局档案不分工作区**：profile 只存 state.profile，注入到所有工作区；如果某个偏好只适用于单一项目，应留在该区记忆而不是全局档案。profile 默认置顶、不参与淘汰；取消置顶后超过 `profileKeep` 的旧条目会标为 archived（不物理删除），全部置顶时宁可控量也不动用户明确保留的规则。
- **多话题拆分是启发式的**：认空行、行首编号/项目符号、少量连接词，以及「整条消息至少 2 个问号，且下一句以新发问/新对象开头」的连续问句；含代码围栏的消息整条不拆，最多 3 个区。拆错时可在面板合并或改范围。
- **多话题回答按编号分发**：助手回答能解析出 1..N 编号时，各段落到对应工作区；解析不出时只写主区，不会把整段回答复制到所有活跃区。
- **只认真实用户消息**：`[Plugin context from ...]` 与 `dsh-ops:step-tail` / `batching-guidance` 注入不会建区、不记账、不注入；其他插件若用不同 source 形式注入，仍可能被当成用户消息。
- **迁移匹配是词面的**：只按 token/IDF 命中，不做语义同义改写；真实回放里出现过中文关键词匹配不到英文 plugin 的跨语言漏搬。未命中内容留在来源区，可用 `mode:"all"` 或预览里的低分候选/逐条补选兜底。搬空的迁移归档不能恢复，只有来源仍有剩余内容时才可恢复。迁移只动工作区，不动全局档案。
- **路由解释是事后记录**：trace 只保留最近 50 条，解释字段来自当时的评分与分支；LLM 改写决策时仍保留原始 `scores`，但不保留 LLM 的推理文本。
- **导出默认包含全局档案**：`state.profile` 会随工作区一起导出（`withProfile:false` 可关闭）；导入时按规范化文本去重合并，不覆盖现有档案。工作区导入仍重编 id/名称，失败整批回滚。
- **费用只到会话级**：cost-meter 桥接显示的是会话总费用；多工作区会话无法精确分摊到区，且服务不可用时整块隐藏。
- **测试数据**：默认测试只用合成数据（`test/fixtures/synthetic-questions.json`），不含生产凭据、门店、会员或设备信息；任何真实问题 fixture 都不随仓库发布，已在 `.gitignore` 排除。
